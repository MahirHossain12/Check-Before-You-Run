# Pilot protocol

## Question and hypothesis

Does requiring novice Python learners to commit to an expected output before running a test improve immediate independent counterexample design? The directional hypothesis favors predict-first. The comparison estimates the combined effect of committing a prediction before execution and seeing that prediction alongside the result.

## Assignment and tasks

Target eight adult Python beginners for a small formative pilot, one per sequence. Screen for basic ability to read a Python function, compare numbers, and recognize min and max. Give everyone the same brief orientation using an unrelated sample. Each learner completes four rounds, two per condition. Four cyclic topic orders crossed with complementary ABBA and BAAB condition orders put each topic in each condition and each position. Randomly assign the eight sequence slots before running sessions. Record incomplete sessions separately and report actual counts and missing slots.

Keep test choices, materials, and instructions fixed across conditions. During practice learners select one input and receive the candidate's Python-verified output. After each practice task, show a parallel problem with a new context and threshold. The learner submits an input and its specification-derived output without running the candidate. Delay corrective feedback until the end.

## Scoring

- Primary outcome — a valid counterexample requires both a failure-inducing input and a correct specification-derived output.
- Secondary outcomes — failure-inducing input selection, correct expected output, practice input selection, and correct judgment of the observed practice output. Prediction accuracy is available only for B.
- Report the number of complete sessions and success counts per condition. Average each participant's two scores per condition and report the mean of the participant-level B minus A differences. Show individual paired values to illustrate variation. Treat these estimates as descriptive.
- Every candidate has a seeded fault. The result applies to finding faults under the supplied task instructions. Correct judgments about passing practice inputs can be reported separately. Immediate transfer can reflect carryover across conditions and does not establish durable learning.

## Session logistics

Confirm the applicable institution and program requirements before recruiting or collecting learner data. Obtain consent through the applicable process. Use an anonymous code, leave real responses out of public repositories, and allow participants to stop. Tell them the session concerns checking short Python functions, the activity is voluntary, and submitted test choices and answers are recorded. At the end, disclose that all candidates contained deliberately selected errors and walk through the four misconceptions.

The HTML stores responses in memory until export. Closing or reloading discards that session. Record withdrawals or technical problems in a private session log. A public demo export is marked walkthrough, and demonstration records are labeled synthetic. If real sessions cannot take place in time, report implementation and technical verification in the SOP.
